# จัดการสมาชิกสำหรับผู้ดูแลร้าน

ระบบนี้ต่อยอดหน้าจัดการสมาชิกเดิม ใช้บัญชี Supabase Auth ที่ยืนยันอีเมล ยินยอมเงื่อนไข และได้รับสิทธิ์ใน `private.member_admins` เท่านั้น ไม่มี PIN หรือสิทธิ์จาก localStorage/user_metadata และไม่เปิด CRUD ให้บุคคลทั่วไป

## วิธีใช้

1. เข้าสู่ระบบด้วยบัญชีที่ได้รับสิทธิ์ แล้วเปิด **จัดการสมาชิก** บนเมนู desktop หรือ mobile
2. **เพิ่ม**: กรอกชื่อ อีเมล และโทรศัพท์ แล้วส่งคำเชิญ เจ้าของบัญชีเปิดอีเมล ตั้งรหัสผ่าน และยินยอมเงื่อนไขเอง ไม่มีการยืนยันอีเมลแทนผู้ใช้
3. **ดู**: รายชื่อแบ่งหน้าละ 25 คน พร้อมสถานะยืนยันอีเมลและสถานะผู้ดูแล
4. **แก้ไข**: กดแก้ไขเพื่อดู/เปลี่ยนชื่อ โทรศัพท์ และที่อยู่ กดบันทึกหรือยกเลิก ถ้าบันทึกล้มเหลว ข้อมูลที่กรอกจะยังอยู่เพื่อแก้ไข/ลองใหม่ตามสถานการณ์
5. **ลบ**: ต้องยืนยันก่อนลบบัญชีส่วนกลางอย่างถาวร ห้ามลบบัญชีตนเองหรือบัญชีที่มีสิทธิ์ผู้ดูแล การลบมีผลกับข้อมูล profile ที่ผูกบัญชีด้วย

## ขอบเขตข้อมูลและสิทธิ์

- `admin-users` ตรวจ Auth identity จริง สถานะยืนยันอีเมล ความยินยอม และสิทธิ์จากฐานข้อมูลทุกคำขอ ก่อนเรียกบริการที่มีสิทธิ์สูง
- Update รับเฉพาะ `action`, `id`, `name`, `phone`, `address`; ไม่รับการเปลี่ยนอีเมล รหัสผ่าน บทบาท consent หรือ referral ผ่าน endpoint นี้
- Profile เป็นแหล่งข้อมูลชื่อ/ที่อยู่หลัก ไม่เขียนกลับไปยัง Auth user_metadata และไม่สร้างแหล่งข้อมูลซ้ำ
- รหัสสมาชิกต้องเป็น UUID, ชื่อ 1–100 ตัวอักษร, โทรศัพท์ไม่เกิน 30, ที่อยู่ไม่เกิน 1,000; ตรวจบนเซิร์ฟเวอร์ ไม่อาศัย maxlength ใน UI อย่างเดียว
- บัญชี/profile ที่ไม่พบหรือถูกลบระหว่างบันทึกจะตอบ 404 ไม่รายงานบันทึกสำเร็จ
- ไม่เพิ่มสิทธิ์ UPDATE ของตารางให้ anon/authenticated; service-role key อยู่เฉพาะ Edge Function และไม่บันทึกใน frontend
- การเปลี่ยนสิทธิ์ผู้ดูแลทำโดยเจ้าของโครงการผ่านช่องทางจัดการที่เชื่อถือได้ ไม่ใช่จากหน้า CRUD นี้
- ไม่ลบบัญชีลูกค้าจริงหรือส่งอีเมลคำเชิญอัตโนมัติในการทดสอบ

## ตรวจรับและเผยแพร่

```powershell
npm test
npm exec --yes --package=deno@2.9.6 -- deno check --no-lock supabase/functions/admin-users/index.ts
# กำหนด PLAYWRIGHT_MODULE เป็นโมดูล Playwright ที่ติดตั้งไว้ก่อน:
node tests/browser/membership.cjs
git diff --check
```

Browser tests ใช้ SDK/UI จริง แต่จำลอง HTTP provider และบล็อกการเรียก Supabase จริง ทดสอบ CRUD, ข้อผิดพลาดระหว่างบันทึก, ข้อความ HTML ที่ต้องไม่ทำงาน, focus/keyboard, isolation, non-admin และจอ 1440/390px จึงไม่ใช่หลักฐานว่ามีการลบหรือแก้บัญชีจริง

ต้อง deploy **เฉพาะ `admin-users`** และอ่านโค้ดบนเซิร์ฟเวอร์กลับมาเทียบก่อนยืนยัน backend พร้อมใช้ หน้าเว็บใหม่ต้องเผยแพร่ผ่าน GitHub Pages แยกจาก Edge Function; การแก้ไฟล์ใน worktree หรือ deploy backend ไม่ได้เผยแพร่ `index.html` โดยอัตโนมัติ ไม่ deploy/แก้ `send-auth-email` ในงานนี้ และยังต้องคงค่า rate limit/secret ที่ผู้ใช้ตั้งไว้อย่างปลอดภัย
